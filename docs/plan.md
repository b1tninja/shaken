# Portfolio position

This file is generated by sdk-forge/forge.py from the portfolio plan, and a hand edit here is
overwritten at the next run. Two documents govern this project and they govern different things:
the obligation table in [../ROADMAP.md](../ROADMAP.md) governs protocol work - which rows exist,
and what evidence closes one - and this file governs sequencing, which is which wave this
project sits in, what has to exist before it can ship behaviour, and what must not be started
while it is unfinished. [PORTFOLIO.md](../../PORTFOLIO.md) at the workspace root is the
authority on both, so a change to a tier, a wave or an arrow is made there and regenerated here,
never the other way round.

## Position

**Tier 4, wave 5** - the rest in tier order, one at a time. Tier 4 is hold: a real protocol with
a weaker case for now, whether through adequate incumbents, a narrow audience or a long
dependency chain.

## Depends on

- **asn1core** - a PASSporT is only as trustworthy as the certificate the originating provider
  publishes at its x5u, and parsing that certificate is asn1core's job, not shaken's. **Status:
  does not exist yet.** There is no asn1core project and no asn1core code: the workspace holds
  only its extraction plan at ../../asn1core/PLAN.md.

**Blocked, not in progress.** asn1core does not exist yet, so shaken cannot ship behaviour until
asn1core does. A roadmap row that parses, encodes or verifies a DER structure is not deferred
work here: it is gated on a project that has no code and no test suite. Any plan, milestone or
release note that cites asn1core says blocked rather than in progress, and no release of shaken
is promised before asn1core has one of its own.

## Sequencing rules

- At most two projects in the portfolio carry real effort at once. A third is not started, and
  no obligation is taken here, while those two are open.
- No new shell is created while any Tier 1 project still has an unimplemented obligation.
  Twenty-eight generated READMEs are already the maintenance liability, and the failure mode of
  this portfolio is prose outrunning code rather than under-building.
- A project freezes to Tier 4 when its first release finds no external user, and a shell is
  retired publicly when a competitor ships what it promised rather than left to rot - the
  retirement is announced, not a README quietly left to go stale.

Protocol facts come from docs/rfc-map.md and the RFC Editor record, never from memory. This file
positions the work; it is not a source for anything a row cites.
