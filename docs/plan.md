This file is generated by `projecthub shells generate` from the portfolio plan. Change the plan,
not this file: a hand edit here is never overwritten, but it stops the generator from updating
the file at all. Two documents govern this project and they govern different things: the
obligation table in [../ROADMAP.md](../ROADMAP.md) governs protocol work - which rows exist, and
what evidence closes one - and this file governs sequencing, which is which wave this project
sits in, what has to exist before it can ship behaviour, and what must not be started while it
is unfinished. [PORTFOLIO.md](../../PORTFOLIO.md) at the workspace root is the authority on
both, so a change to a tier, a wave or an arrow is made there and regenerated here, never the
other way round.

## Position

**Tier 4, wave 5** - the rest in tier order, one at a time. Tier 4 is hold: a real protocol with
a weaker case for now, whether through adequate incumbents, a narrow audience or a long
dependency chain.

## Depends on

- **pkix** - a PASSporT is only as trustworthy as the certificate chain behind its x5u, and
  `verify.verify_request()` has to validate that chain to an STI trust anchor. That is RFC 5280
  path validation, which is pkix's job. **Status: shell with some rows done.** Its
  `anchors.load_anchor()` and `chain.candidates()` rows are `[ok]`; `validity.check_signature()`,
  `validity.check_validity()` and `result.validate()` are still `[ ]`, so the chain-validation row
  here (`credentials.chain-validation`) is blocked on them. This corrects an earlier "Depends on:
  None" (and the generated text that named only asn1core): reading a certificate is not the same
  as trusting it.
- **asn1core** - parsing the certificate and the TN Authorization List extension is asn1core's
  codec at work, not shaken's. **Status: exists as code.** `credentials.load_certificates()` and
  `tnauth.parse_tn_auth_list()` consume `asn1core.cert.parse_certificate` and `asn1core.node.decode`
  and have passing tests, so the rows that parse DER are no longer deferred. asn1core is a
  read-only sibling: it is imported by sibling path (`pythonpath` in `pyproject.toml`) and never
  edited from here. It has no TNAuthList decoder of its own, so shaken carries a small one.
- **cryptography** (third party, not a sibling) - ES256 signing and verification only; the one
  importing module is `shaken/jws.py`. The owner's rule is that cryptographic primitives may come
  from this package and every wire format is ours.

**Gated by coverage, not by absence.** pkix path validation is the remaining gate. No release of
shaken is promised before pkix has one of its own.

## Sequencing rules

- At most two projects in the portfolio carry real effort at once. A third is not started, and
  no obligation is taken here, while those two are open.
- No new shell is created while any Tier 1 project still has an unimplemented obligation. The
  READMEs of the 27 generated shells are already the maintenance liability, and the failure mode
  of this portfolio is prose outrunning code rather than under-building.
- A project freezes to Tier 4 when its first release finds no external user, and a shell is
  retired publicly when a competitor ships what it promised rather than left to rot - the
  retirement is announced, not a README quietly left to go stale.
