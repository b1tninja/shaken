# Portfolio position

This file is generated by `projecthub shells generate` from the portfolio plan. Change the plan,
not this file: a hand edit here is never overwritten, but it stops the generator from updating
the file at all. Two documents govern this project and they govern different things: the
obligation table in [../ROADMAP.md](../ROADMAP.md) governs protocol work - which rows exist, and
what evidence closes one - and this file governs sequencing, which is which wave this project
sits in, what has to exist before it can ship behaviour, and what must not be started while it
is unfinished. [PORTFOLIO.md](../../PORTFOLIO.md) at the workspace root is the authority on
both, so a change to a tier, a wave or an arrow is made there and regenerated here, never the
other way round.

## Position

**Tier 4, wave 5** - the rest in tier order, one at a time. Tier 4 is hold: a real protocol with
a weaker case for now, whether through adequate incumbents, a narrow audience or a long
dependency chain.

## Depends on

- **asn1core** - a PASSporT is only as trustworthy as the certificate the originating provider
  publishes at its x5u, and parsing that certificate is asn1core's job, not shaken's. **Status:
  exists as code.** It has source files and a test suite of its own, and its own README states
  its release status. That it exists does not say it provides what a row here needs: which
  capability a row consumes is decided row by row.

**Gated by coverage, not by absence.** asn1core now has code and a test suite, so shaken is no
longer waiting for the project to exist. It is still waiting for the structures it needs: a
roadmap row that parses, encodes or verifies a DER structure cites the asn1core capability it
consumes, and stays deferred until that capability has a passing test there. No release of
shaken is promised before asn1core has one of its own.

## Sequencing rules

- At most two projects in the portfolio carry real effort at once. A third is not started, and
  no obligation is taken here, while those two are open.
- No new shell is created while any Tier 1 project still has an unimplemented obligation. The
  READMEs of the 27 generated shells are already the maintenance liability, and the failure mode
  of this portfolio is prose outrunning code rather than under-building.
- A project freezes to Tier 4 when its first release finds no external user, and a shell is
  retired publicly when a competitor ships what it promised rather than left to rot - the
  retirement is announced, not a README quietly left to go stale.
